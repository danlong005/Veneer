# Trying Veneer on a free IBM i: PUB400

[PUB400](https://pub400.com) is a free public IBM i. Sign up on its website and you get a
user profile and a library of your own, with 5250 access over telnet and SSH on port
2222. It's a good place to try Veneer when you don't have an IBM i of your own.

PUB400 is shared by many users, so you can't run Veneer on it as a server job. Run Veneer
on your own machine instead, and it connects to PUB400 over the internet as an emulator
does.

## Point Veneer at it

In `.env` (development) or the `veneer.env` file of an installed release:

```sh
VENEER_HOST=pub400.com
VENEER_PORT=992
VENEER_TLS=true
VENEER_LISTEN_HOST=127.0.0.1
VENEER_LISTEN_PORT=8080
```

Port 992 is telnet over TLS. PUB400's certificate is issued by a public authority
(Sectigo) for `pub400.com`, so Veneer verifies it as it is: leave `VENEER_TLS_CA` blank and
`VENEER_TLS_REJECT_UNAUTHORIZED` at `true`. To check the certificate yourself:

```sh
openssl s_client -connect pub400.com:992 -servername pub400.com </dev/null \
  | grep -E 'subject=|issuer=|Verify return code'
```

`Verify return code: 0 (ok)` means Veneer will accept it. Port 23 also works, with
`VENEER_TLS=false`, but your password then crosses the internet unencrypted, so use 992.

Keep `VENEER_LISTEN_HOST` at `127.0.0.1`. Browsers on your own machine can reach Veneer,
and nobody else can.

Then start Veneer and browse to http://localhost:8080:

- From the source: `npm install`, `npm run build`, then `npm start` (or `npm run dev`,
  which also turns on the designer for your machine).
- From a release archive: unpack it, copy `veneer.env.example` to `veneer.env` and set the
  lines above, then `node packages/server/dist/main.js --config veneer.env`. Add
  `VENEER_DESIGNER=local` to use the designer from your machine.

## Sign on

With these settings, the first page is PUB400's own sign-on screen. Sign on with your
PUB400 user profile and password, as in an emulator. Veneer doesn't keep the password.

PUB400 also allows automatic sign-on (`QRMTSIGN` is `*VERIFY`), so Veneer can show its own
sign-on page instead. Its `QPWDLVL` is `3`:

```sh
VENEER_SIGNON=auto
VENEER_QPWDLVL=3
```

Veneer's page accepts a password only over HTTPS or from a browser on the same machine,
so this works with the settings above. Automatic sign-on hasn't been tried on PUB400 yet.

## Run something

To run programs from your library, add it to the library list first:

```
ADDLIBLE MYLIB
CALL MYPGM
```

[Order Desk](https://github.com/danlong005/OrderDesk) is a small RPG order system with
menus, subfiles, pop-up windows and help, written to show Veneer's auto-transform. It
builds into your PUB400 library in a few minutes. Its README has the steps.

## Sign off before closing the tab

Use `SIGNOFF` (or your menu's sign-off option), then **Disconnect**. Closing the tab also
works: Veneer ends the session after `VENEER_RESUME_GRACE_SECONDS`. But until then, the job
stays active on a shared system.

## What to know about PUB400

- **Code page 273.** PUB400 is in Germany, and its system CCSID is 273 (German). Veneer
  reads and sends text as CCSID 37, or 1047 if set, and 273 isn't supported. Letters,
  digits and most punctuation (`$ # % & * ( ) - + = . , : ; ' " / ?`) are the same in both.
  These may show as other characters, and typing them may send others:
  `! @ [ ] { } \ | ~ ^ ¢ ¬ §` and `ä ö ü Ä Ö Ü ß`. If your password contains one of
  them, signing on may fail.
- **Shared and limited.** All access is logged, support is limited, and you can't run
  long server jobs or change system settings. Be polite to the other users.
- **No Digital Certificate Manager for users.** You can't assign certificates, so HTTPS to
  Veneer is up to the machine Veneer runs on (see [TLS and HTTPS](../deploy/README.md#tls-and-https)).
